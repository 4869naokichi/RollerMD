# RollerMD

ローラー駆動用モータドライバのファームウェアです。STM32F303K8T6（NUCLEO-F303K8）を対象とした STM32CubeIDE プロジェクトで、エンコーダから推定した角速度に対し、PI 制御と外乱推定による補償を行います。

本リポジトリは既存のファームウェアを共有するためのものです。実機の回路図・配線図、ホスト側の指令生成プログラム、動作確認結果は含まれていません。使用するハードウェアに合わせて設定を確認してください。

## 主な機能

- **角速度制御**：エンコーダ（設定値 2048 PPR、4 逓倍）のカウントから角速度 [rad/s] を算出
- **制御周期**：1 ms（TIM6 割り込み）
- **制御器**：PI 制御（PID 形式で実装、現在の微分ゲインは 0）＋外乱推定・補償
- **モータ出力**：TIM1 の PWM 出力を使用。指令の符号で正転・逆転を切り替え
- **指令受信**：USART2、115200 bps、8N1。独自の 10 バイトフレームで角速度指令を受信
- **状態出力**：USART2 にデバッグ用テキストを約 100 ms ごとに出力

詳しい仕様は [制御の実装](docs/control.md)、[通信プロトコル](docs/uart-protocol.md)、[ピン配置・周辺機能](docs/hardware.md) を参照してください。

## プロジェクトの開き方

1. リポジトリを取得します。

   ~~~sh
   git clone https://github.com/4869naokichi/RollerMD.git
   ~~~

2. **STM32CubeIDE** を起動し、既存の Eclipse / STM32CubeIDE プロジェクトとしてクローン先の `RollerMD` フォルダをインポートします（`.project` と `.cproject` を含むフォルダです）。
3. プロジェクトをビルドします。必要に応じて IDE が要求するツールチェーンや STM32Cube ファームウェアを設定してください。
4. ターゲットの配線・電源・安全措置を確認した後に、ST-LINK 等で書き込み／デバッグを行ってください。

**注意：** `RollerMD.ioc` を新しい STM32CubeMX / STM32CubeIDE で再生成すると、設定や生成コードが変わる可能性があります。元のプロジェクトを複製し、差分を確認してから再生成してください。ここに記載した操作はコードから確認した一般的な導入手順であり、本リポジトリに対して新規ビルドや実機動作試験を実施したものではありません。

## 通信の概要

- 受信する指令値は **角速度 [rad/s] の 32-bit 浮動小数点数（little-endian）**です。
- 受信フレームは `"START"`（ASCII 5 バイト）＋ 指令値 4 バイト ＋ XOR チェックサム 1 バイトの **計 10 バイト**です。
- `+INFINITY` は制御器内部のリセット指令として判定されます。ただし、モータ出力を確実に遮断する安全停止指令ではありません。
- 通信で応答 ACK を返す処理はなく、代わりに状態表示用の文字列を周期的に送信します。

フレームのバイト配置と具体例は [UART プロトコル](docs/uart-protocol.md) を参照してください。

## 使用上の注意・既知の制約

- **通信途絶時のタイムアウト停止や、独立した非常停止機能は実装されていません。** 最後に受信した角速度指令が残り得ます。実機では外部の安全回路・停止手段を用意してください。
- 指令値がゼロ、または `+INFINITY` の場合、PI 制御部分の積分状態や出力をリセットしますが、その後で外乱補償値を加算しているため、**最終 PWM が必ずゼロになるとは限りません**。
- 現在有効なゲインとモータモデルは、ソースコード中で「下のローラー」と記載されたものです。「上のローラー」用の定数はコメントアウトされています。接続するモータと機構に応じた再同定・調整が必要です。
- 出力制限は PWM 設定値の `-950` ～ `950`（タイマ周期 `999`）ですが、積分器にアンチワインドアップ処理は実装されていません。
- 実装されているフレーム検証は XOR チェックサムのみです。機器保護やセキュリティのための通信認証ではありません。
- 実機に接続する前に、ピン配置、モータドライバの入力仕様、回転方向、エンコーダ分解能、電源仕様、PWM 波形を確認してください。
